# T013 — Implement Spawn Constraints (Q→U Rule + Duplicate Cap)

**Phase**: 3 — Word Logic
**Session estimate**: 45 min

## Input
- T008 complete: `Column.gd` has `_pick_letter()` method with basic weighted random
- T009 complete: `GameManager.active_tiles` array is populated via `register_tile()`

## Steps

This task upgrades `Column.gd._pick_letter()` — it does NOT create new files.

### 1. Add `_last_spawned_letter` tracking
- Already declared in T008 — confirm it persists correctly across spawns

### 2. Implement Q→U rule
```gdscript
# At the top of _pick_letter(), before weighted selection:
if _last_spawned_letter == "Q":
    _last_spawned_letter = "U"
    return "U"
```

### 3. Implement simultaneous-duplicate cap
```gdscript
# After initial letter selection:
var active_letters: Array = GameManager.active_tiles.map(func(t): return t.letter)
var attempts := 0
while active_letters.count(letter) >= 2 and attempts < 10:
    letter = _weighted_random()
    active_letters = GameManager.active_tiles.map(func(t): return t.letter)
    attempts += 1
# After 10 failed attempts, accept whatever letter was last picked
```

### 4. Refactor weighted selection into a private `_weighted_random() -> String`
- Moves the pool-building + `_rng.randi() % pool.size()` logic into its own method
- Lets both `_pick_letter()` and the retry loop call it cleanly

### 5. Add `_last_spawned_letter` update at end of `_pick_letter()`
```gdscript
_last_spawned_letter = letter
return letter
```

### 6. Unit-test the rules manually
Add a temporary `_test_spawn_rules()` function callable from `_ready()` (behind an `if OS.is_debug_build()` guard):
- Simulate 20 letter picks, print results
- Manually verify Q is followed by U
- Count same-letter occurrences across printed sequence

### 7. Remove test code, commit updated `scripts/Column.gd`

## Acceptance Criteria
- Play for 60 s with 5 columns: scan Output panel — after every "Q" in a column's spawn sequence, the NEXT spawn in that column is "U"
- No letter appears simultaneously in 3 or more active tiles at the same time (scan active_tiles every second via a debug print to verify)
- Weighted distribution is not broken: "E" appears far more than "Z" over a 2-minute play session
- No crash or infinite loop when the retry cap of 10 is hit (add a print warning if attempts == 10)
- No GDScript errors; Column.gd committed

## Notes
- The duplicate cap applies across ALL active tiles in the scene, not per-column — this prevents a "wall of E" scenario
- The 10-attempt cap prevents an infinite loop when the letter pool is naturally constrained (e.g. late game where 4 of the same letter are somehow active at once)
- This task touches ONLY `Column.gd` — no other files change
