# T005 — Write Palette.gd Static Class

**Phase**: 1 — Environment Setup
**Session estimate**: 15 min

## Input
- T002 complete: `scripts/` directory exists, project opens without errors

## Steps
1. Create `scripts/Palette.gd` with a `class_name Palette` declaration (not an autoload — just a named class)
2. Define the default colour palette as static constants:
   ```gdscript
   class_name Palette

   const BACKGROUND: Color = Color(0.055, 0.039, 0.118)  # #0e0a1e deep violet
   const TEXT: Color = Color(1.0, 1.0, 1.0)              # white
   const PILE_WARN: Color = Color(1.0, 0.2, 0.2)         # danger red

   const COL_COLOURS: Array[Color] = [
       Color(0.0,   0.784, 0.722),  # col 0 — teal
       Color(0.0,   0.878, 1.000),  # col 1 — cyan
       Color(1.0,   0.757, 0.027),  # col 2 — amber
       Color(0.694, 0.404, 1.000),  # col 3 — violet
       Color(0.0,   0.941, 0.502),  # col 4 — mint
   ]
   ```
3. Verify `class_name Palette` is visible in Godot editor's class autocomplete (open any .gd file and type `Palette.` — constants should appear)
4. Commit `scripts/Palette.gd`

## Acceptance Criteria
- `scripts/Palette.gd` exists and is committed
- File parses without GDScript errors (check Godot Output panel)
- In the editor, typing `Palette.BACKGROUND` in any script shows autocomplete — confirms `class_name` is registered
- `Palette.COL_COLOURS.size()` equals `5` (verifiable via a one-line test expression in the editor's GDScript REPL if needed)

## Notes
- `Palette.gd` is a static data class — it must NOT extend Node or be registered as an autoload
- This class is used by LetterTile (T007), Column (T008), and HUD (T015) without coupling them to ThemeManager
- ThemeManager (registered in T002 as a stub) will eventually overlay these defaults with theme-specific values, but Palette is always the fallback
