# T004 — Create words_en.txt Word List (50k+ entries)

**Phase**: 1 — Environment Setup
**Session estimate**: 30 min

## Input
- T002 complete: `assets/data/` directory exists

## Steps
1. Obtain a clean English word list with ≥ 50,000 lowercase words, one per line:
   - **Option A (preferred)**: Download the SCOWL word list at size 60 from `http://wordlist.aspell.net/dicts/` — the `en_US-large.dic` file after stripping affix codes gives ~60k words
   - **Option B**: Use the MIT-licensed `words_alpha.txt` from dwyl/english-words on GitHub (370k words) and filter to 3–15 character words using a short Python script:
     ```python
     with open("words_alpha.txt") as f:
         words = [w.strip() for w in f if 3 <= len(w.strip()) <= 15]
     with open("words_en.txt", "w") as f:
         f.write("\n".join(words))
     ```
2. Verify the file: `wc -l assets/data/words_en.txt` must return ≥ 50,000
3. Verify format: `head -5 assets/data/words_en.txt` — all lowercase, no spaces, one word per line
4. Remove any entries containing non-ASCII characters: `grep -P '[^\x00-\x7F]' assets/data/words_en.txt | wc -l` should return 0
5. Check estimated file size stays under 1 MB: `ls -lh assets/data/words_en.txt`
6. Commit `assets/data/words_en.txt`

## Acceptance Criteria
- `wc -l assets/data/words_en.txt` ≥ 50,000
- `grep -c '^[a-z]\{3,15\}$' assets/data/words_en.txt` equals the total line count (all entries valid)
- File size ≤ 1 MB
- Common test words validate: `grep -x 'cat' assets/data/words_en.txt` returns `cat`; `grep -x 'storm' assets/data/words_en.txt` returns `storm`
- File is committed in git

## Notes
- WordValidator.gd (T011) will load this file via `FileAccess` and build a Dictionary at startup
- Plain `.txt` one-word-per-line is intentional — no JSON overhead, smaller file, simpler parser
- Do not include proper nouns, abbreviations (no dots), or words shorter than 3 characters
